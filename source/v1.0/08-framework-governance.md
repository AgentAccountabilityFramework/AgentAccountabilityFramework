# 8. Framework Governance

The framework’s governing body, decision rights, and versioning process remain undefined. The repository’s procedures cover contributions, review, and repository releases.

## Contributing

Open a [GitHub issue](https://github.com/spineless-simp/AgentAccountabilityFramework/issues) for a question, correction, or substantial proposal. Open a [pull request](https://github.com/spineless-simp/AgentAccountabilityFramework/pulls) for a focused edit. Identify the affected sections or controls and explain the problem, the proposed outcome, and any supporting evidence. See the [contribution guide](../../CONTRIBUTING.md) and [guide to proposing changes](../../contributing/proposing-changes.md). Email [admin@agentaccountabilityframework.org](mailto:admin@agentaccountabilityframework.org) for general questions or matters that need a private conversation. The [Code of Conduct](../../CODE_OF_CONDUCT.md) applies to participation and explains how to report concerns.

## Review and decisions

Maintainers review issues and pull requests within their repository permissions. Review considers the problem, evidence, clarity, fidelity to the framework, and effects on readers and implementers. Record the reasoning and any unresolved disagreement for substantive proposals. See [repository governance](../../GOVERNANCE.md). Label changes to framework requirements as proposals until the source baseline is explicitly superseded. Merging a related repository edit leaves the framework baseline in force.

## Releases

The [release guide](../../maintenance/releases.md) describes checks for a repository release. Release authority, versioning, and publication require separate agreement.
