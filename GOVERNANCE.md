# Repository governance

This page describes how to participate in repository work. It does not establish a governing body or decision process for the AAF itself. The source describes framework governance separately in [Section 8](source/08-framework-governance.md).

Maintainers with repository access can review issues and pull requests, manage project spaces, and make repository changes within their permissions. Contributors can propose and discuss changes through issues and pull requests; access to merge is not a prerequisite for contributing. The [contribution guide](CONTRIBUTING.md) describes the process.

Review should consider the problem, supporting evidence, clarity, source fidelity, and effects on readers and implementers. For substantive proposals, record the reasoning and any unresolved disagreement in the issue or pull request. A merged repository edit does not by itself amend the source framework: proposed framework changes must be identified as proposals until the source baseline is explicitly superseded. See [proposing changes](contributing/proposing-changes.md) and the [source index](source/README.md).

The [Code of Conduct](CODE_OF_CONDUCT.md) applies to participation. The [moderation](maintenance/moderation.md) and [release](maintenance/releases.md) pages offer maintainer guidance; they do not confer permissions or establish release authority.
